JAVASCRIPT VALIDATION LOGIC (plain English)
Every form uses the novalidate attribute so our own messages show. On submit, script.js
runs one validator function per field. Each returns an empty string if the value is fine,
or an error message. Messages appear under the field. If any field fails, the submit
event is cancelled (preventDefault) and the first bad field gets focus. Fields are also
re-checked when the user leaves them.
Registration: all fields required; username 5+ characters (letters, numbers, underscore);
valid email; phone 8-15 digits only; password 10+ characters with uppercase, lowercase,
number and special character; confirm password must match; gender selected; at least one
genre; country chosen.
Booking: required fields not empty; valid email; phone with 10+ digits; screening
date/time not in the past; tickets a whole number above 0; payment method chosen.
Voucher: exactly 12 digits. Online payment: digits only; 16 digits for Visa/Mastercard,
15 for Amex. Billing email must be valid.
Dynamic booking behaviour: cost = movie price x tickets x ticket-type multiplier
(Adult 1.0, Child 0.6, Student 0.8) and updates on every change. Voucher or card fields
show only for the chosen payment method (the hidden fieldset is also disabled so it is
not posted). "Same as email address" copies the email into the billing email.
Carrying the movie to the booking page: movie and recommendation links go to
booking.html?movie=<id>. The booking page reads this query string with URLSearchParams
and selects the matching option in the dropdown. The user can still change it.
Recommendation rules: movies not allowed for the age group are removed (Child: G, PG;
Teen: G, PG, M; Adult: all). Remaining movies score +3 for matching genre and +2 for
matching viewing preference; movies with a score above 0 are shown best first.
Watchlist (bonus): movie ids are kept in an array saved in localStorage, so the list
survives page changes. Add/remove buttons update it; watchlist.html rebuilds the list.
